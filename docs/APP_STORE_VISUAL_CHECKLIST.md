# Lumen Run App Store Visual Checklist

Use this checklist before every beta or App Store screenshot pass. The goal is to make Lumen Run look like one coherent game, not separate generated mockups.

## Core Read

- The Relay Core must be visible within the first second of any preview image.
- Three route rings should read as playable lanes, not decorative orbital graphics.
- Lumen Sparks need a clear positive signal: gold, bright, and preferably with a small `+` badge where space allows.
- Glitch Shards need a danger signal before color is considered: triangular frame, sharp silhouette, or broken shape.
- Void Gates should look disruptive, not lethal: purple interrupted arc, broken signal, and lower opacity than lethal hazards.
- Oversync should read as a state change: brighter route rings, warmer HUD accent, and clear countdown or ending effect.

## Screenshot Set

Capture these scenes for a first App Store pass:

1. Start screen
   - Show the Relay Core mark, title, one dominant start CTA, and the lower utility dock.
   - Background signal field should stay subtle enough that the core mark is the focus.

2. Early gameplay
   - Show Stage 1 with Spark and Shard visible.
   - HUD should be readable at thumbnail size: score, route progress, and pause/settings only.

3. Route clear / module pick
   - Show the centered module choice screen.
   - At least one common module and one visually distinct role header should be visible.

4. Oversync gameplay
   - Show the player in Oversync with brighter route effects and the countdown visible.
   - Use a frame where hazards converting to score is visually obvious.

5. Game over / progress
   - Show final score, best score context, rewards, and a restart path.
   - Avoid using a failed run that looks empty or low-energy.

## UI Rules

- Do not show more than one primary CTA in a screenshot.
- Avoid opening every utility surface on the start screen. Rewards, records, object guide, and settings are supporting surfaces.
- Keep panels compact with 8px or lower corner radius.
- Prefer monospaced digits for score, route progress, timers, and records.
- Avoid generic neon gradients that do not connect to the object language.
- If a screenshot needs explanatory text, the visual underneath must still be understandable without that text.

## Localization Check

- Korean screenshots should use Korean UI as the default App Store set for Korea.
- English screenshots should not contain Korean-only teaching labels.
- Object names must match the IP bible vocabulary: Relay Core, Lumen Spark, Glitch Shard, Void Gate, Oversync, Relay Module.

## Rejection Criteria

- The icon and start mark use different core silhouettes.
- Sparks and hazards rely only on color difference.
- Start screen looks like a settings hub instead of a game start.
- HUD covers gameplay or competes with tap timing.
- Module cards look like generic list rows rather than attachable game modules.
- Any App Store image looks like a disconnected AI mockup instead of the actual playable game.
